Self-hosted agents

Agents that keep the keys.

You write the agent with the AI SDK. chamvi queues its runs, checkpoints every step, pauses for approvals and resumes interrupted runs, in your own Node process and database.

Get startedRun lifecycle

What the AI SDK leaves out

The layer between a model call and an agent you can trust.

  • 01

    One intake for every trigger

    A webhook, a cron tick or a manual call becomes the same envelope and the same queued run. Idempotency keys turn redeliveries into the existing run; concurrency keys keep two runs for one issue apart.

    dispatch({ idempotencyKey })

  • 02

    Runs survive restarts

    A checkpoint after every step. drain() hands unfinished runs back, and recover() continues them from the latest checkpoint on any replica, without applying a recorded effect twice.

    drain() → recover()

  • 03

    Ask before acting

    A tool call that needs a human pauses the run in waiting, with a signed resume token. Approve or deny it an hour or a day later, from any replica.

    resume(token, { approved })

How a run flows

Seven statuses, one store.

Every run lives in your store, from dispatch to its final status. Whatever stops it halfway, the next execution starts from the latest checkpoint.

Packages

Small today, planned in the open.

The engine, the cron scheduler, the HTTP and MCP API, the TypeORM store, the GitHub connector, sandboxes, notifiers and the test helpers ship now. The rest is designed milestone by milestone.

@chamvi/coreshippedAgents, triggers, the run engine, checkpoints, budgets, effect tools, approvals, agent state and the in-memory store. Reference→@chamvi/test-kitshippedControllableClock and the store contract suite every IStore implementation must pass. Reference→@chamvi/schedulershippedFires cron() triggers once per tick across replicas, with overlap policies, timezones and one-shot jobs. Reference→@chamvi/store-typeormshippedTypeORM store (PostgreSQL) for durable runs across replicas, passing the store contract suite. Reference→@chamvi/httpshippedREST, server-sent events, webhooks and an MCP endpoint, with bearer, authup and OIDC authentication. Reference→@chamvi/githubshippedGitHub App auth, webhook triggers and issue tools with reconciliation. Reference→@chamvi/sandbox-*shippedDisposable workspaces, local for development, a container or a pod per workspace in production, plus coding tools.
