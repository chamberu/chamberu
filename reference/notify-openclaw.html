@chamvi/notify-openclaw ​

The OpenClaw notifier. The public API of packages/notify-openclaw/src/index.ts.

bash
npm install @chamvi/notify-openclaw @chamvi/core --save

@chamvi/core is a peer dependency; the notifier uses the global fetch. See OpenClaw for the setup.

openclaw ​

ts
function openclaw(options: OpenclawNotifierOptions): INotifier;

const DEFAULT_HOOKS_PATH: '/hooks';
const OPENCLAW_TIMEOUT_MS: 30_000;
const OPENCLAW_REQUEST_ERROR_CODE: 'openclaw_request';
const MESSAGE_BODY_MAX_LENGTH: 8_000;
ts
/** Where OpenClaw delivers the agent turn's answer; both `channel` and `to` are concrete. */
export type OpenclawDelivery = {
    /** E.g. `telegram`, `slack`, `whatsapp`; `last` is refused by OpenClaw for hooks. */
    channel: string;
    /** The recipient on that channel (chat id, user, number). */
    to: string;
    /** Selects one of several accounts of the channel. */
    accountId?: string;
};

export type OpenclawNotifierOptions = {
    /** Default `'openclaw'`. */
    name?: string;
    /** The OpenClaw gateway, e.g. `http://openclaw:18789`; a base path is kept. */
    baseUrl: string;
    /** OpenClaw's `hooks.token` (a hook-dedicated token, not the gateway token). */
    hooksToken: string;
    /** OpenClaw's `hooks.path`, default `/hooks`. */
    hooksPath?: string;
    /** The OpenClaw agent that phrases the message (must be in `hooks.allowedAgentIds` when set). */
    agentId?: string;
    deliver: OpenclawDelivery;
    /**
     * A link to the approval in the chamvi UI, e.g.
     * `https://<app>/ui/approvals?run=<runId>&approval=<approvalId>`, where the
     * signed-in owner answers it; it carries no token.
     */
    approvalUrl?: (ref: {
        runId: string; 
        approvalId: string; 
        agent: string 
    }) => string;
    /**
     * Also put the resume token and a ready-made `resume_run` MCP call into
     * the message, default `false`: the OpenClaw agent then holds the token,
     * and with `agent:<name>:approve` on its MCP principal a prompt injection
     * in the body can make it approve.
     */
    resumeTool?: boolean;
    /** Default `OPENCLAW_TIMEOUT_MS` (30 s). */
    timeoutMs?: number;
    clock?: IClock;
    fetch?: typeof globalThis.fetch;
};

/** The body of `POST <hooksPath>/agent`. */
export type OpenclawHookBody = {
    message: string;
    name: 'chamvi';
    agentId?: string;
    deliver: true;
    channel: string;
    to: string;
    accountId?: string;
};

Throws InvalidAgentDefinitionError for an empty name, hooksToken, agentId, deliver.to or deliver.accountId, a deliver.channel that is empty or last, a baseUrl that is no absolute http:/https: URL or carries credentials, a query or a hash, a hooksToken that fetch could not send as a header (a control character, a character above U+00FF, surrounding whitespace), a hooksPath that does not start with / or is / (trailing slashes are dropped, so /hooks/ posts to /hooks/agent), an approvalUrl that is no function, a resumeTool that is no boolean and a timeoutMs that is no positive integer.

ts
const notifier = openclaw({
    // the OpenClaw gateway, reachable from the app
    baseUrl: 'http://openclaw:18789',
    // OpenClaw's hooks.token, not the gateway token
    hooksToken: process.env.OPENCLAW_HOOKS_TOKEN ?? '',
    // placeholders: the channel and recipient of your OpenClaw setup
    deliver: { channel: '<channel>', to: '<recipient>' },
    // optional: a link to the approval in the UI, without the token
    // (only resumeTool: true puts the token and a resume_run call into the message)
    approvalUrl: ({ runId, approvalId }) => `https://chamvi.example/ui/approvals?run=${encodeURIComponent(runId)}&approval=${encodeURIComponent(approvalId)}`,
});

const engine = new Engine({
    store: new MemoryStore(),
    agents,
    // agents name it with notify: 'openclaw'
    notifiers: { openclaw: notifier },
    resumeSecret: process.env.RESUME_SECRET ?? '',
});

The request ​

notify(n, { idempotencyKey }) sends one POST <baseUrl><hooksPath>/agent:

PartValue
authorizationBearer <hooksToken>
idempotency-keyidempotencyKey, or sha256:<hex> of it when it is longer than 256 characters or holds anything but visible ASCII
bodyOpenclawHookBody: { message, name: 'chamvi', agentId?, deliver: true, channel, to, accountId? }

The message is deterministic for one notification (no clock value, no random id), so a resend after a lost response is byte-identical and OpenClaw replays it:

chamvi notification. Relay it to the user; keep every link and id exactly as written.

<title>

<body, cut to MESSAGE_BODY_MAX_LENGTH characters>

Agent: <agent>
Run: <runId>

Expires: <expiresAt ISO>
Approve or deny: <approvalUrl({ runId, approvalId, agent })>
Or call the chamvi MCP tool resume_run with {"token":"<token>","approved":true} to approve, or "approved":false to deny.

For an approval with resumeTool: true the first line reads keep every link, id and token exactly as written. instead. The last block is sent for approvals only; Approve or deny only with approvalUrl (and a notification that carries an approvalId, as every engine approval does), the resume_run line only with resumeTool: true. With neither, the block ends with Answer it in the chamvi UI (or through POST /runs/:id/approve); this message carries no resume token. instead. approvalUrl gets the run id, the approval id and the agent, never the token, so by default (resumeTool: false) the token is nowhere in the request (URL, headers or body); see Deployment: OpenClaw. A cut body ends with … (cut, <n> more characters) and never splits a surrogate pair.

Failures ​

Any 2xx resolves. Every other status throws a ChamviError with code openclaw_request and the message OpenClaw <status>: <response text> (plus (retry after <value>) for a Retry-After header); a network failure throws OpenClaw request failed: <message> (<cause message>) (undici keeps the detail, such as ECONNREFUSED or ENOTFOUND, in cause), a send that takes longer than timeoutMs OpenClaw did not answer within <ms>ms. (the timer runs on the clock and aborts the fetch). The response text and the network failure message are cut to 500 characters after the hooks token and the resume token (sent with resumeTool only) were replaced by [redacted], so an endpoint that echoes the request never puts either into onError.
